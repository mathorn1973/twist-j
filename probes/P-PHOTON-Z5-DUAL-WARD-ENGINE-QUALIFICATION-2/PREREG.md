## Field 1: exact carrier and reproduced incident

For one orbit heat bath, let the nonempty ordered candidate list have integer
exponents

```text
e_0,...,e_(r-1),          1 <= r <= 5,
m=min_i e_i,
q_i=e_i-m,
w_i=2^q_i,
W=sum_i w_i.
```

The exact conditional law chooses the unique index `j` satisfying

```text
sum_(i<j) w_i <= U < sum_(i<=j) w_i,
U uniform on {0,...,W-1}.
```

The inherited implementation formed every `w_i` and `W` in `uint64_t`.  It
raised exactly `orbit_integer_weight_overflow` before reading a random bit if
some `q_i >= 63`, and raised exactly `orbit_weight_sum_overflow` if an ordered
addition overflowed.  Even after both tests passed, its `bounded(W)` computed
`bit_length(W-1)` and its `bits(count)` rejected a count above 63.  Thus
`W>2^63` raised exactly `bitstream_bits_width_exceeds_63`, also before reading
a random bit.  Those three guards are reproduced as historical engineering
behavior, not treated as a scientific terminal.

The fixed high-level envelope is not an arbitrary vector.  For `L in {6,8}`
put `S=L^2`, take two disjoint translated homologous positive coordinate
two-tori `P_0,P_1`, the hard state `n=-P_0`, the generator `g=P_1`, and level
`s=S`.  Exactly `k=0,1,4` remain in the hard orbit.  In that order,

```text

support              S       2S      2S
B=1[j!=0]+1[H_2!=0]  1       0       1
e=-support+sB        0      -2S     -S
```

Thus the exponent spread is exactly `2S`: the frozen vectors are
`(0,-72,-36)` at `L=6` and `(0,-128,-64)` at `L=8`.  The old guard must fire

fixed synthetic integer envelopes.

## Field 2: qualified exact sampler

`orbit_qualification.cpp` owns a nonnegative `ExactUInt` implemented entirely
in standard C++17.  Values through `UINT64_MAX` use a no-allocation inline
representation.  Larger values spill to a normalized little-endian vector of
base-`2^32` limbs, with no leading zero limb.  The backend implements exact
comparison, addition, increment, checked subtraction of a representable
`uint64_t`, left shift, multiplication, bit length, checked `uint64_t`
conversion and canonical decimal output.  Exponent distances use an
order-preserving unsigned key, so even the complete signed-64-bit span is
computed without signed overflow.  No floating point, `__int128`, host
intrinsic or third-party arithmetic is admitted.

Silent backend known-answer tests freeze canonical zero and demotion, inline
maximum, carry into real dynamic storage at `2^64`, shifts through `2^192`,
bit lengths, comparison, multiplication above `2^128`, decimal conversion,
checked-conversion rejection, subtraction-underflow rejection, excessive-shift
rejection and the complete signed exponent span.  These tests must execute the
dynamic-limb path rather than merely test values that fit inline.

The exact bounded sampler puts

```text
b=bit_length(W-1),
```

reads exactly `b` consecutive MSB-first bits as an integer, accepts iff that
integer is below `W`, and otherwise rejects the complete draw and repeats.
For `W=1`, `b=0`, the unique draw is zero and consumes no bit.  This is exact
unbiased rejection from `{0,...,W-1}`; no floating point, modulo reduction,
saturation or host PRNG is permitted.

The SHA-256 counter stream deliberately remains the inherited compatibility
stream:

```text
SHA256(ASCII domain || 16 seed bytes || 16 counter bytes),
domain = photon-z5-dual-mobility-qualification-1,
```

with unsigned 128-bit big-endian counter from zero and bits consumed
most-significant-bit first.  Keeping this deterministic synthetic domain makes
old-path bit parity directly comparable; it is neither a formal attempt ref
nor a CROSSCHECK seed.

The replacement has two paths.  If every shift is below 63, the inherited
ordered `uint64_t` sum does not overflow, and `bit_length(W-1)<=63` (equivalently
`W<=2^63`), it must call the old bounded-u64 path without an intervening bit
read.  Otherwise it uses the `exact-uint` path.  On every old-defined table,
old and new must have the same selected index, draw, number of consumed bits,
and following stream bits.  A change to any formerly defined small-span
transition or random-bit offset is a qualification failure and would require
a fresh mobility qualification before later use.

The frozen known-answer spans are

```text
0, 1, 32, 62, 63, 64, 72, 128, 192.
```

They include the path boundary, both reproduced formal-size spreads and a
larger reserve.  A separate span-62 vector with weights
`(2^62,2^62,1)` and total `2^63+1` reproduces
`bitstream_bits_width_exceeds_63` with zero bits consumed.  Another span-62
vector whose ordered sum exceeds `2^64-1` reproduces
`orbit_weight_sum_overflow`.  Both must pass through `exact-uint`.

The prospectively fixed bounded engineering smoke is exactly one sample for
each of those nine span tables, the width-overflow table, the sum-overflow
table and the two L6/L8 two-plane tables.  Each sample starts a fresh stream
with seed bytes
`00,01,...,0f`, counter zero and the frozen domain above.  It records the
selected index, exact draw and consumed-bit count.  There is no runtime size,
seed, repetition-count or table selector.

The full frozen small-span envelope is exhaustively enumerated over every
ordered candidate vector of length one through five whose normalized shifts
are in `{0,...,8}` and include zero: exactly 28,981 ordered tables and
6,791,443 integer draws.  For each table, the audit compares exact old/new
weights and totals, compares the selected index for every integer draw
`0,...,W-1`, and compares one deterministic old/new sampling transcript:
choice, draw, consumed-bit count and the following 63 stream bits.  All these
small tables are old-defined.  This is a finite exhaustive table-and-selection
audit; it makes no claim to enumerate the infinite set of possible rejection
transcripts.

For every audited table and every ordered pair `i,j`, the verifier checks

```text
w_i/w_j = 2^(e_i-e_j)
```

by exact cross multiplication.  On one orbit the heat-bath transition is
`P(i,j)=w_j/W`, hence

```text
w_i P(i,j)=w_i w_j/W=w_j w_i/W=w_j P(j,i).
```

The algebra establishes the exact conditional target and detailed balance;
the finite tests audit its implementation.  It is not a mixing theorem.

## Field 3: synthetic supervisor qualification

`supervisor_qualification.py --fixture` opens only synthetic local children.

record must preserve the failing specification, both return codes, both

A single two-worker fail-fast batch first holds one blocking
`engine+reader` sibling live, then runs the `dual_rc` trigger in the other
worker and queues four further jobs.  The trigger's nonzero returns cause one
shared cancellation decision.  The live sibling must be killed and reaped;
at least two genuine queued futures must be cancelled, and any wrapper already
dequeued in the race must observe cancellation before spawning a child.  All
futures must finish, no queued child body may start, and the final surviving
PID count must be zero.  All waits, output reads and diagnostic buffers are
bounded.  Any timeout, cap violation, collector failure or unreaped process is
a verifier failure.

Two deterministic fault injections also exercise cleanup before normal batch
coordination: reader creation fails after the engine exists, and thread start
fails after both children exist.  Each path must preserve its exact injected
error, kill and reap every created direct child under an absolute deadline,
and leave zero survivors.  Worker and collector threads are daemonized only as
a last interpreter-exit firewall; the accepted path still joins them within
the frozen bound.

These are process-supervision tests only.  The child payload contains no
dual state, Ward statistic or production input.  The fixture qualifies the
direct engine and reader children; neither synthetic child creates a process
descendant, so no claim about killing an independently spawned descendant
tree is made.  The scheduler may cancel three or four of the queued futures;

transcript are frozen.

The verifier launches each compiler, orbit fixture and supervisor in its own
Linux/POSIX session.  The supervisor's direct engine and reader children
inherit that session and do not create another process group.  Its ordinary
cleanup kills and reaps each direct child.  Independently, the verifier drains
