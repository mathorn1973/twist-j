## 1. Executable scope and provenance

`verify.py` uses only the Python standard library and exact integer/Fraction
arithmetic. It reads adjacent `dp5_tableau.hpp` as ASCII data, imports no
scientific candidate, performs no floating simulation, writes no files and
uses neither randomness nor network. Successful output is one deterministic,
sorted, compact ASCII JSON line with an explicit LF on `sys.stdout.buffer`.

The restricted header reader accepts literal `Q{integer,positive_integer}`
entries between unique `BEGIN_A/END_A`, `BEGIN_B/END_B`, `BEGIN_C/END_C`
markers, requires the 49+7+7 array entries, and compares them with an
independent exact transcription. It is not a C++ parser and does not prove
that the compiled kernel uses the table correctly.

The DP/order/Hermite and norm fixtures are inherited from
`P-U-CA40-DP5-384-COMPARISON-1`, with its earlier DP5/grid attribution retained.
The new checks concern contiguous absolute-time geometry, unitary chaining
and reset-sensitive counterexamples. The design and intended acceptance
conditions were visible to the author: this is supporting algebra, not a
blinded numerical replication. No previous floating outcome is an oracle.

## 3. New geometry and continuity support

Each block lasts exactly `1/20480000` seconds. At the first occupied segment,
A uses consecutive N512 cells, with checkpoints after `4,8,12,16`; C uses
N384 cells, with checkpoints after `3,6,9,12`. All four blocks are adjacent.
The complete occupied prefix lasts `1/5120000` seconds. Absolute segment
onsets remain 16 for `(4,3),(4,4)` and 64 for `(1,1)`, with both signs.

Exact checks establish vanishing active indicators before those onsets,
equal A/C checkpoint times, adjacency, absence of an amplitude switch inside
the prefix, nonnested certificate grids and the correct DP denominator 768.
The 1008 stage checks are `6 cases * 4 blocks * 3 cells * 2 halves * 7 nodes`.
Different cases can have different physical times; these are same-case A/C
comparisons, not common-time intercase coherences.

Six rational two-dimensional chains use an exactly orthogonal rotation,
explicit local vector errors and cumulative L1 error majorants. At four
successive checkpoints they verify norm preservation, carried states,
nondecreasing cumulative budgets and the triangle bound without a growth
factor. Separate counterexamples expose a reset state, an erased accumulated
budget, mutable snapshot aliasing, a wrong polynomial constant and summing
already cumulative totals. A final fixture shows that increasing upper
bounds need not imply increasing actual error.

These finite fixtures support the general Duhamel/continuity argument in
`DERIVATION.md`; they are not a proof that the executable did not reset its
state. The actual harness must check the carried state and all Certificate
arrays at 270 checkpoint transitions, `poly[0]` against the incoming vector
at every cell, and nondecreasing cumulative components. The runner validates
these counters, checkpoint inventories, saved component monotonicity and
source/artifact custody. Source review checks the implementation of those
assertions. Monotonicity alone would not exclude a state reset.

The 120 thermal columns are unnormalized and unchanged. Column 36 is
`(0,0,0,0,0,0,3)`, with weight `20^7/21^10`; checkpoint-zero flat indices 36
and 396 preserve the previously exposed targets. No target is exempted from
the all-2880-column comparison or bound screen.

## 4. Separate gates and limits

The numerical campaign uses A,C,C,A and the pairs 1/2 and 4/3. Same-arm
five-payload byte equality, cumulative-column endpoint consistency,
`E_C <= E_A` for every checkpoint/case/column, and the exact strict sum of
two observed end-to-end times are runtime decisions. The exact gate does
not predict any of them. Two timing observations have descriptive medians,
not confidence intervals.

An exact PASS also does not establish the model's physical admission,
thermal-tail closure, source/reference preservation, full-word accuracy,
common-time channel accuracy, interval-library/compiler correctness or the
floating implementation of DP5. It does not authorize a long run, retry,
retuning, adaptive continuation or a Canon fold. A numerical negative or
incomplete result is retained under the preregistered contract.
