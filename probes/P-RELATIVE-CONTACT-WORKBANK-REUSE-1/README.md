# Workbank reuse with retained copied records

NON-CANONICAL / L1. Proposed input to Public Canon v109; current authority
remains v108. Reservation: https://github.com/mathorn1973/twist-j/issues/1878.

This candidate combines the actual v108 write word with a supplied explicit
bank copier and reversed work. The same two workbanks can return to their
blank preparation while two separate permanent banks retain the input record.
Three successive experiments use one fixed program on 101 slots, with every
old input, temporary value and archive included. The prepared family contains
all 1000 ordered triples from the ten-input v108 family.

The construction pays for six fresh permanent archive banks, two workbanks,
three prepared inputs and the shared controls. Complete account is 290,
including common auxiliary account 248. Account is conserved; archive
capacity is consumed at the declared cycle boundaries. No retained archive
is erased or made fresh again.

Read PREREG.md for the frozen executable contract, PROOF.md for the exact
copying and finite-horizon construction, and PROVENANCE.md / SOURCES.tsv for
source exposure and custody. verify.py is the self-contained standard-library
verifier; WORD535.txt is the unchanged v108 word. EXPECTED.txt, RUN.md and
RESULT.md are added only after the public source pin and completed replay.

## What would constitute a real v109 advance

- An explicit contact-only copy operation for the actual five-symbol bank
  code, with the working source bank restored at each module boundary.
- Restoration of the complete active source, clock, controls and both
  workbanks after writing, copying and reversing the work, with the copied
  record retained at its own addresses.
- One fixed schedule for three independent preloaded inputs, and a proved
  family for every specified finite horizon with explicit stock scaling.
- A precise separation of restored workspace, occupied permanent storage,
  preparation account and retained-history capacity.

The independent mathematical review must accept the new copy and composition
proofs and inspect the actual frozen program before any Canon fold. Required
computation checks must replay the same source and output on x86_64 and
aarch64. These are concrete inputs for a later reviewed v109 content fold,
full activation, tag and release; this probe does not change authority.

The existing finite common-apparatus theorem remains valid at its original
scope. The extension does not establish indefinite operation on one finite
carrier, regeneration of occupied retained archives, an autonomous choice of
the next input, raw-input synthesis, contact-only compilation of the supplied
loading swaps, native-U realization, a global monotone freshness function,
or a thermodynamic law. The 12-contact local and 60-contact bank words are
upper bounds here; the attachment's shortest-word search is not promoted.
