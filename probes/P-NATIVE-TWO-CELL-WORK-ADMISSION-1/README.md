# Native exchange versus the two-cell paid-record proposal

PUBLIC / NON-CANONICAL / L1. A. M. Thorn; Apache-2.0.
Claim [#1616](https://github.com/mathorn1973/twist-j/issues/1616).

This probe retains the concrete N=2 work target of #1612 and tests one
literal implementation using the five native preparations of #1615.
It compares that proposal with the native two-slot exchange already proved
in #994, and classifies a restricted family of its conserved energy readings.

The intended distinction is operational: a present native receiver state
must change, rather than its desired history being evaluated inside a
decoder using the original source label and counter.

- [PREREG.md](PREREG.md): frozen scope, audit ranges and falsifiers.
- [PROOF.md](PROOF.md): exact native/work comparison and scoped proofs.
- [SOURCES.tsv](SOURCES.tsv): source custody and historical attribution.
- [verify.py](verify.py): standalone exact audit, no source imports.

The primary fixed-checkpoint reading has a two-tick collision witness.
The literal b lift also fails on a refused source; affine bank readings
vanish while nonlinear odd scalar readings do exist. The entire bounded
work carrier is larger than one native checkpoint at common counter.

Separately, actual stable b exchanges centered native piston blocks and
their declared even energy, including occupied blocks. These are internal
blocks of one checkpoint, not the two field-chain cells. This exchange
does not implement the selected H15->5+10 contact or its pointer. Native
evolution permits nonproportional positive quadratic energies, so the
physical energy-selection question survives even on this positive example.

Run from repository root after the public pin:

    python3 probes/P-NATIVE-TWO-CELL-WORK-ADMISSION-1/verify.py
