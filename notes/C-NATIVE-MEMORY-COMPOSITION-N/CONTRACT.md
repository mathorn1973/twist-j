# Common interface for a subsequent record construction

2026-10-29. NON-CANONICAL. Analytical specification; not an executed
probe or prospective registration. Any scientific test needs its own
new source, pre-run pin, predicates, budgets, and result record.

## Objects that must be fixed together

1. Name the complete carrier and update. State whether it is the single
   original U, an already defined coupled architecture, or a new law.
   A decoder output must not be silently fed back into the original U.
2. Give a common-counter preparation map for every admitted message or
   message history. Fix source, memory, target, reference and clock roles.
   Declare whether these are raw coordinates, quotient variables, or
   encoded observables. Account for any preparation correlations.
3. Give a total readout on its complete domain. BLANK must differ from
   occupied zero. State whether it reads the counter, reference, or
   accumulated history. Do not change it between interventions.
4. State the retention interval and reading boundaries. Permanent
   checkpoint-only completion after synchronization is excluded for one
   unchanged native U by PROOF.md Section 5; a finite-horizon contract is
   different and must specify its length in advance.
5. Before the alleged use, require the complete target and every
   coordinate outside the declared varying memory block to be equal
   across the compared messages.
   Prove that the compared states are reachable at the same counter.
   After use, verify both the declared target effect and the retained
   record, using the same fixed interfaces.
6. For another independently selectable message, name its physical
   carrier, all message-pair preparations, the receiving event and the
   state of the earlier archive. Replaying a prior message is not a
   second arrival. A single five-state family has only five selectable
   histories regardless of elapsed time.
7. Include the clock/program, coupling, initial cleanliness or source
   coherence, and any energy/readout assumptions needed by the chosen
   larger architecture. A conditional finite construction is acceptable
   if those premises are explicit.

## Failure conditions to put before a future run

A claimed source-to-memory-to-target witness fails its stated interface
if the target already carries the payload at the comparison boundary,
the other context differs, a required input is unreachable, the previous
record is lost during use, or the readout or coordinate roles change.
A claimed repeated-arrival witness additionally fails if its new message
is only a deterministic rereading of the old one, if some declared input
history is absent, or if a reset/input/coupling is inserted outside the
declared update. A claimed all-future permanence needs proof; finitely
many successful clocks do not establish it.

These are typed obligations. Their failure does not prove that every
other realization is impossible. They prevent the two existing witness
families from being concatenated without an actual matching state and
an allowed connecting evolution.
